Module 2: Core Concepts

The Signal-Based Philosophy

Mozek is not just another UI library; it is designed from the ground up to embrace Angular's new reactive primitive: Signals. But why does this matter to you as a developer?


Professor's Note: Think of Signals as variables that can notify the framework when their value changes. This removes the need for Zone.js to guess when to re-render, making your apps lightning-fast.
Signals vs. RxJS

Historically, Angular developers relied heavily on RxJS (Observables, BehaviorSubjects) to manage state. While incredibly powerful for handling asynchronous events (like HTTP requests or WebSockets), RxJS is often overkill for simple UI state (like "is this drawer open?").


Mozek uses Signals for synchronous UI state. This means:

  • No more `async` pipes for simple component state.
  • Glitches are gone: Signals ensure that dependencies are evaluated in the correct order.
  • Fine-grained reactivity: Angular updates only the exact parts of the DOM that changed, not the entire component tree.
How Mozek Uses Signals

Under the hood, almost every property in a Mozek component is backed by a Signal. When you bind an input to a Mozek component, we react to changes instantly without needing `ngOnChanges`.


This ensures that your components are always in sync, your code is easier to read, and your app's performance stays top-notch.
